# 面试讲解指南

用于快速、结构化介绍项目。建议按“背景 -> 架构 -> 难点 -> 结果”表达。

## 1. 一句话介绍

这是一个基于 Spring Boot + React 的全栈博客系统，覆盖内容发布、互动、搜索、通知与 AI 辅助，具备可部署和可维护的工程能力。

## 2. 架构拆解

### 2.1 前端

- React + TypeScript + Vite
- 组件化页面与路由拆分
- 统一 API 层与错误处理

### 2.2 后端

- 控制层 -> 服务层 -> 数据访问层
- JWT 认证 + 权限控制
- 事件驱动处理非核心链路

### 2.3 基础设施

- MySQL：核心业务数据
- Redis：缓存与热点访问优化
- Elasticsearch：全文搜索
- Kafka：消息与异步任务

## 3. 可以重点讲的技术点

### 3.1 搜索链路治理

- 问题：联想输入会污染热词统计
- 处理：接口增加跟踪开关与来源标记，统计层过滤噪声数据
- 结果：热词质量提升，统计含义更稳定

### 3.2 详情页增强

- 问题：用户阅读后缺少继续浏览路径
- 处理：接入增强详情接口，展示上下篇和相关推荐
- 结果：阅读链路更完整，内容发现能力提升

### 3.3 AI 输出治理

- 问题：模型返回包含不应展示的思考片段
- 处理：应用层统一过滤并标准化输出
- 结果：用户界面只展示目标文本，体验可控

## 4. 性能与稳定性

- 通过缓存减少高频读压力
- 把非关键流程异步化，降低主链路时延
- 脚本化健康检查降低发布风险

## 5. 常见追问与回答要点

### Q1：为什么要引入 Kafka？

- 为了把通知、统计等非核心流程异步化，降低接口同步耗时，并提升峰值稳定性。

### Q2：为什么搜索用 ES？

- MySQL 适合结构化查询，ES 在全文检索、分词和相关性排序更有优势。

### Q3：如何保证发布可控？

- 统一脚本、构建校验、健康检查、可回滚产物是基本保障。

### Q4：你做过最有价值的修复是什么？

- 通常可讲“影响用户体验 + 可量化结果 + 可复用方案”的问题，例如搜索统计治理。

## 6. 表达建议

- 先说目标，再说方案，最后说结果
- 用“问题-决策-权衡-结果”结构，不堆砌术语
- 避免讲与岗位无关的实现细节
