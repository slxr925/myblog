# 设计模式应用说明

本文档总结项目中常见设计模式与其价值。

## 1. 策略模式（Strategy）

- 场景：不同业务条件下选择不同处理逻辑（如排序、过滤、限流策略）
- 价值：减少 if/else 扩散，便于扩展

## 2. 工厂模式（Factory）

- 场景：按类型创建处理器或客户端实例
- 价值：隐藏构造细节，统一创建入口

## 3. 观察者模式（Observer / Event）

- 场景：评论、点赞、关注后触发通知与统计
- 价值：解耦主流程与扩展流程

## 4. 门面模式（Facade）

- 场景：对外提供统一服务入口，内部编排多个子系统
- 价值：降低调用复杂度

## 5. 模板方法（Template Method）

- 场景：统一处理流程，不同步骤由子类或策略实现
- 价值：复用主流程，控制变更点

## 实践原则

- 优先解决真实复杂度，不为模式而模式
- 模式引入后要能降低维护成本
- 在代码评审中关注“可读性与扩展性”的平衡
